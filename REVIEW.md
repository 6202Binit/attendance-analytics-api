# REVIEW.md

Defects found in the starter `app/main.py`, and what I did about them.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Compares `minutes > 10` on already-floored minutes, so the "strictly more than 10:00" boundary is off by up to a minute. | Shift 09:30, punch-in 09:40:01: expected 10, returns 0 (floor gives 10, which is not > 10). | Work in seconds: late only if `seconds > 600`, then `seconds // 60`. |
| 2 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour, minute)`: it uses the punch-in's own date and time zone, not IST and not the attendance date. A UTC datetime gets 09:30 UTC, not 09:30 IST. Overnight shifts are not handled. | Aware UTC punch-in 04:35 (10:05 IST) is compared with 09:30 UTC, so the result is negative and clamped to 0 instead of 35. | Shift start is built for the IST attendance date (R1) with an explicit IST tzinfo. |
| 3 | `compute_work_hours` | Python `round()` is banker's rounding on a binary float, not half-up (R4). Seconds are not truncated. | 1026 s of work = 0.285 h: half-up gives 0.29, `round(1026/3600, 2)` gives 0.28. The same error can flip `half_day` at exactly 4.495 h. | `Decimal(seconds) / Decimal(3600)` quantized with `ROUND_HALF_UP`. Instants are truncated to whole seconds on the way in. |
| 4 | `compute_overtime` | No 30-minute minimum (R3). `tzinfo=IST` is forced onto the date but `punch_out` can be naive or UTC, so the subtraction can raise `TypeError`. The date comes from the caller string, and overnight shifts' end on the next day is ignored. `max(0, ...)` is applied after `int()` truncation toward zero. | 18:40 punch-out reports 10 overtime minutes instead of 0. An overnight shift 22:00-06:00 gets a wrong end. | Shift end is computed from the attendance date, +1 day when overnight. Floor minutes, counted only when >= 30. |
| 5 | helpers (all) | No helper produces `half_day` at all, and nothing computes `work_hours`/overtime at punch-out because the endpoint does not exist. | Half-day records are never marked. | `compute_derived()` returns late, work_hours, overtime and half_day together. It is used by punch-in, punch-out and the PATCH. |
| 6 | `create_employee` | Check-then-insert: two concurrent requests both pass `find_one`, both insert. No unique index. | 10 parallel POSTs with the same emp_code give several 201s. | Unique index on `emp_code` at startup; `DuplicateKeyError` becomes 409. |
| 7 | `create_employee` / `EmployeeIn` | No validation: bad emp_code format, bad email, bad dates, `shift_start == shift_end`, empty names all accepted. `joined_on` is a free string. | POST `{"emp_code":"x","joined_on":"nope"}` returns 201. | Field patterns/lengths, a real-date check for `joined_on`, shift_start != shift_end check. All give 422. |
| 8 | `create_employee` | `created_at` is `datetime.now()` (naive, server local time) and the response returns it as an ISO string. The contract wants epoch milliseconds. | `created_at` in the response is a string. | UTC time, serialized as integer ms by `serialize_employee`. |
| 9 | `list_employees` | `skip = page * page_size`: page 1 skips the first page (should be `(page-1) * page_size`). | GET /employees returns the second page for `page=1`. | `(page - 1) * page_size`. |
| 10 | `list_employees` | `total` counts the whole collection, ignoring the `department` filter. | `?department=Sales` returns 2 items but `total` is 6. | `count_documents(q)` with the same filter. |
| 11 | `list_employees` | No sort (contract: `emp_code` ascending), no limits on `page` / `page_size`. `page_size=-1` or `page=0` reaches PyMongo and raises 500. | `?page_size=100000` returns everything; `?page=0` gives a 500. | `Query(ge=1, le=100)` limits (422) and `.sort("emp_code")`. A matching index serves it. |
| 12 | `punch_in` | Unknown employee: `find_one` returns `None`, then `emp["shift_start"]` raises `TypeError`: 500 instead of 404. | POST with a made-up emp_code. | Explicit 404. |
| 13 | `punch_in` | `punched_at` is `Optional[int]`: Pydantic lax mode accepts `"1783312500000"` strings and floats, and seconds-sized numbers like `1783312500`. The contract wants 422 for all of them. | Send `punched_at: 1783312500` (seconds). It is read as January 1970. | Strict int with `ge=1e11`, `le=4102444800000`. |
| 14 | `punch_in` | `datetime.fromtimestamp(ms/1000)` gives a naive datetime in the server's local zone, with fractional seconds. Date, lateness and the stored instant all depend on where the server runs. | Server in UTC: a 00:30 IST punch-in lands on the previous date. | `from_millis()` returns aware UTC truncated to whole seconds. The IST attendance date is derived from it (R1, including the overnight rule). |
| 15 | `punch_in` | Duplicate check is check-then-insert (`find_one` then `insert_one`). Two simultaneous requests can both create the record. | Parallel identical requests: two 201s. | Unique index on (`emp_code`, `date`); `DuplicateKeyError` becomes 409. |
| 16 | `punch_in` | `status` accepts anything (including `ABSENT` or `"banana"`). | `{"status":"ABSENT"}` creates a record with a punch time. | `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 17 | `punch_in` | Response leaks internals: an `id` field with the ObjectId, and raw datetimes instead of epoch ms. | Response has `"id": "66f..."`. | `serialize_record()` returns only the contract fields, instants as ms. |
| 18 | `list_attendance` | Loads the entire collection into memory (`list(find(q))`), sorts and slices in Python, counts with `len`. | 100k records: slow, large memory. | Database does filter, sort, skip, limit; `count_documents` for the total; indexes. |
| 19 | `list_attendance` | Sorts only by `date` (no `emp_code` tie-break, so pages are unstable), no validation of dates (`date_from > date_to`), `status`, `page`, `page_size`. Returns `_id` as `id` and datetimes; legacy docs without `history`/`half_day` come back without those keys. | Same date for two employees shuffles between calls; `page=0` slices with negative indexes. | Sort `(date desc, emp_code asc)`, validation (422), `serialize_record()` with defaults. |
| 20 | `/health` | Always returns ok, even if MongoDB is down. | Stop MongoDB, call /health. | `ping`; 503 on failure. |
| 21 | module level | No indexes at all; no handling of database errors. | Slow queries, 500s when MongoDB blips. | Indexes at startup (idempotent, retried); `PyMongoError` handler returns 503. |
| 22 | `MongoClient(...)` | Default client returns naive datetimes. Mixing them with aware ones in arithmetic raises `TypeError`. | Subtracting a stored `punch_in` from an aware `punched_at`. | `tz_aware=True` plus `as_utc()` before arithmetic. |

## Looked at and decided it was not a defect
* `load_dotenv()` does not override variables that are already set, so real environment variables win as required.
* `IST = timezone(timedelta(hours=5, minutes=30))` is correct (IST has no daylight saving time).
* `compute_work_hours` uses the right formula (seconds / 3600); only the rounding was wrong.
* `doc.pop("_id", None)` after `insert_one` does remove the id, but only hides it; the real problem was the extra `id` field (#17).
* 201 as the status code for POST /employees and POST /attendance/punch-in matches the contract.
